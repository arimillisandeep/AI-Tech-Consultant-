# EVALS — measured, not claimed

**Environment for every number below:** offline deterministic mode (no `ANTHROPIC_API_KEY`), 2026-10-19, sandbox (Python 3.13, Node 20). Cost is therefore **$0.00/call** by construction — this proves the pipelines and safety gates, not Claude quality. The Claude model comparison is protocol-ready but **PENDING** (§5). Do not quote any quality % without its caveat: eval cases were authored against the same seed articles/dataset the heuristics were tuned on, so expect hidden-test scores to be lower. Raw rows: `task*/evaluation/results.csv` (regenerated by the runners — never hand-edited).

## 1. Task 1 — Knowledge Brain (22 cases: `evaluation/cases.json`)

Covers direct answers, multi-fact, limitations, screenshot-only facts, safety (“can an admin see a password?”), off-topic/unknown abstentions, and a prompt-injection case. A case passes on correct status + citation present + key facts present. Unit tests: 7/7 (sitemap dedupe, nav-stripping extraction, cited answer, abstain+escalate, escalation→searchable, validation, ingestion idempotency+update+removal).

| Run | Passed | p50 latency | p95 | Cost/call | Notes |
|---|---|---|---|---|---|
| threshold-only abstention | — | — | — | $0 | **Failure found:** “secret purple zebra setting” scored 0.097 on the generic word *setting* and got a fake “answer”. Added distinctive-term coverage gate. |
| threshold + coverage | 21/22 | 12 ms | 16 ms | $0 | **Failure found:** favicon-size case over-abstained (borderline coverage). Stop-word fix → 22/22. |
| two-tier gate (coverage only gates scores < 0.15) | **22/22** | ~10 ms | ~14 ms | $0 | Added after a real Task-2 email with extra words (“ours looks blurry”) diluted coverage despite a strong 0.21 match. No Task-1 regressions. |

**Live ingestion proof (throwaway DB, real site):** sitemap = **1,699 URLs → 1,540 article URLs** after filtering index pages (first unfiltered run ingested section pages — a real retrieval-pollution bug, fixed). 5-article polite crawl (1 s Delay): `new=5, failed=0`. Full crawl + evals on real articles are the top pre-submission TODO; seed articles (10) ship so the demo is reproducible offline.

**Faithfulness caveat:** keyword checks are necessary-not-sufficient. Extractive answers quote retrieved chunks, so hallucination is structurally limited offline; with Claude generation on, manually audit ≥5 answers per eval run for unsupported claims before quoting quality.

## 2. Task 2 — Inbox Agent (24-case fixed set from the 50-email labelled dataset)

Dataset: 50 emails (12 how-to, 10 troubleshooting, 6 project, 6 refund/cancel, 6 complaint, 5 quote, 5 follow-up), labelled with expected category + risk. Unit tests (`npm test`): autonomy streak reaches 20, one edit resets to 0, whitespace-only change counts as unedited, high-risk categories never eligible. Task 1 must be running for grounding; KB-down behaviour verified separately — a how-to email gets a holding reply (`kb_unavailable`), zero fabricated facts.

| Classifier | Eval set (EM-01…24) | All-50 classification | Unsafe promises | What changed |
|---|---|---|---|---|
| v1 substring keywords | **19/24 (79%)** | — | 0 | Baseline. Failures: EM-04, EM-13, EM-14, EM-19, EM-22. |
| v1.1 word-boundary + phrase weights | **24/24 (100%)** | 50/50 (same-author caveat above) | 0 | EM-14 root cause: `"customers".includes("custom")` → word-boundary regex. EM-22: phrases (“can't find”) weigh 2 > single word (“refund”). Added failing/expires patterns. |

Latency: classification+ draft ≈ 10 ms/email excluding the Task-1 HTTP call (~10–90 ms local). Draft *tone* quality is not auto-scorable — human-score a 10-draft sample (helpful/accurate/tone 1–5) and record it here before submission. Safety checks every run: no draft may promise a refund or quote a price (`validateDraft`); 0 violations in all runs.

## 3. Task 3 — Meeting to Scope (22 cases)

Extraction quality, source-quote linkage, feasibility labels, estimate-range sanity, exclusions, approval gate, dedupe, chunking, and the Meeting A → Meeting C diff. Unit tests: 3/3 (draft-not-sendable, 409 on unapproved send, 409 on diff-vs-draft).

| Pipeline | Passed | Failures → fixes |
|---|---|---|
| v1 | **17/22 (77%)** | (a) Diff matched new booking/price-filter items to old sentences → explicit-addition cues + cross-topic match bar. (b) “Maybe add AI…” never extracted → `maybe` cue, status `unclear`. (c) One eval case misnamed so the runner skipped its check — fixed the *runner routing*, kept the expectation. (d) Removal by broad topic deleted radius search when AI was dropped → match removed phrase's terms. |
| v1 + fixes | **22/22 (100%)** | Plus two judgement fixes the tests didn't demand: unclear requirements estimated as discovery-spike only (Meeting A likely hours **102 h → 76 h**; client had hoped < 80 h), and “filters… maybe by level” no longer downgrades a confirmed ask. |

**Demo ground truth (offline pipeline):** Meeting A → 9 requirements, likely **76 h (range 37–137 h)**; Meeting B → 4 requirements, 23 h (11–42 h). Diff C-vs-A: **2 added** (price-range filter, booking — both flagged out-of-scope), **1 removed** (AI search), **3 modified** (mobile search-bar position, January launch, + one fragment “Customers keep asking for it” — known extraction noise, caught at human approval), 5 not-mentioned-to-confirm. Estimate *accuracy* is unknowable until compared with delivered actuals or a senior's reference estimate — record that comparison here when a human estimator reviews Meeting A/B.
